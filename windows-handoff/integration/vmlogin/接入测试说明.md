## 现在的手工联通检查

1. 在已经打开的 Temu-DE-Test 浏览器中，新开一个内部扩展管理页 chrome://extensions 。不要刷新现有 Temu 页面。
2. 开启开发者模式，选择“加载已解压的扩展程序”，目录为：

   F:/TemuWindows/handoff-20260907/integration/vmlogin/diagnostic-extension

3. 打开“Temu 接入联通检查（只读）”的弹窗，点击“检查连接”。显示“连接成功”后，本机服务日志会记录来自扩展的请求；这一步不需要商品搜索、截图、绑定或采集。

若不通：检查 VMLogin 端口扫描保护是否允许 37821，以及本地回环是否绕过代理。只处理本地连接条件，不更换已经有效的 IP、代理套餐或浏览器指纹。不要全局关闭保护。

## 正式接入方式

1024 继续只在 VMLogin 配置中提供浏览器网络出口；不把代理密码写进项目配置、Git 或报告。保留当前已验证的国家、会话模式和出口设置。1024 不同套餐的粘性会话时长不同，不能假定固定 120 分钟。

VMLogin 官方支持加载本地扩展。正式扩展目录是 F:/TemuWindows/handoff-20260907/runtime/browser-extension；它包含业务能力，本轮仅加载上面的独立诊断扩展。

如果后续确实需要 CDP，VMLogin 文档说明其本地 API 启动配置后返回浏览器地址，再通过 /json/version 获取调试信息。控制 API 端口和浏览器 CDP 端口是两个概念。系统现有 external_cdp 可以作为接入基础，但 fixedProfile 校验要求普通 Chrome 启动器 marker，VMLogin 必须单独验证目标 Profile、会话和实际 endpoint，不能伪造 marker 或取消正式连接保护。本轮未调用 VMLogin 的 start、stop、skiplock 或配置更新接口，也未自动绑定。

## 0.5GB 下的分阶段验收

- 第 1 阶段（现在）：只验证诊断扩展到本机服务。无数据库、无商品请求、无图片请求。
- 第 2 阶段：用额外临时数据库和只读接口检查现有商品/Review/历史图片；读取已迁移的本地缓存，不补图、不访问远程图片 URL。
- 第 3 阶段需用户明确授权：在当前已打开的德国站页面上，由用户手工检测、绑定，先核对少量商品的 ID、价格、币种、类目与页面一致性。创建测试 Campaign、采集落库、Evidence Session、保存 BEFORE/AFTER 或 Assessment 均需单独明确范围，不能因“运行测试”自动执行。
- 本轮不自动刷新、滚动或搜索 Temu，不批量下载图片，不改变冻结 Snapshot/Image Cache V1。不要为了省流量直接改掉已验证的 VMLogin 浏览器环境；如果以后需要禁图，应使用另一个经确认的测试配置。

联通成功只能证明扩展能到达本地系统，不能证明代理稳定性或商品采集已验收。

## 服务记录与停止

bridge-process.json 记录本次服务 PID；connectivity-checks.jsonl 仅记录检查时间和是否来自扩展，不记录网页、账号或代理信息。

停止联通测试后才可让其他 Dashboard 占用 37821；不要停止未知已有进程。正式服务不能与联通服务同时使用该端口。
