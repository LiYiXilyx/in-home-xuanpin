# Temu 运营人员操作说明书

适用版本：2026年9月9日，本机运营台＋VMLogin中的手动采集插件。本文以当前页面按钮为准。类目自动采集目前停用，自动截图队列是另一项功能。

## 1. 第一次使用：先认识三个地方

| 地方 | 做什么 | 不会自动做什么 |
| --- | --- | --- |
| 本机运营台 | 创建、暂停、切换任务；建立正式池；查看跟踪；导出 | 打开运营台不会开始采集 |
| VMLogin中的Temu页面及手动插件 | 看商品，识别类目，检测、绑定和提交当前已加载商品 | 不会替你滚动或点击See more |
| 周期跟踪页面 | 为固定商品池保留基线，归档后续观测，展示曲线 | 不会定时自己去Temu抓取 |

日常页面顺序：上方是“新建采集任务”，下方是“已有商品复采（周期跟踪）”。下方同时提供旧任务继续、暂停释放占用、复采商品合并正式池的操作。

## 2. 开始前的准备

1. 在本机工作目录双击“启动Temu运营台.vbs”。当前目录为 `F:\TemuWindows\handoff-20260907`。已经能打开运营台时，不必重复启动。
2. 在普通浏览器或Codex中打开 `http://127.0.0.1:37821/#catalog`。运营台的本机页面与VMLogin中的Temu商品页面分开操作。
3. 打开VMLogin中日常使用的Temu配置，人工进入要采集的类目。
4. 确认德国站、English、EUR和Top Sales，等待商品列表显示。不要在搜索结果页、商品详情页上创建类目采集绑定。
5. 确认手动插件面板已出现。安装/更新插件由维护人员处理；更新后需要在扩展管理页重新加载插件，再刷新Temu页面。平时无需反复重新安装。
6. 查看运营台“当前采集任务”的类目和名称，避免把数据提交到错误任务。

关闭网页标签不等于暂停任务。如果要换类目，先按第7节释放占用。

## 3. 先选对入口

| 你现在要做什么 | 应点哪个入口 |
| --- | --- |
| 第一次采集一个没有正式池的新类目 | 插件“识别当前类目”→运营台“选择当前类目”→“开始首次采集” |
| 继续昨天没有采完的任务 | 下方“已有手动任务”选择旧任务→“切换 / 继续所选任务” |
| 更新已有商品价格、销量、评论 | 下方选择正式池→“创建复采任务并切换”；已有复采任务可直接继续 |
| 从已采数据中把新品加入正式池 | “预览所选复采任务的合并结果”→“确认合并到正式池” |
| 单独开一轮、按数量目标寻找新品 | 上方“继续补充商品（创建新任务）” |
| 把数据给同事看 | 导出Excel；导出不是建立池，也不是创建跟踪计划 |

推荐日常用法：新类目先建立首个正式池；以后使用复采任务更新数据，采到新品后按需合并正式池。这样既能更新已有商品，也能利用已经采到的新品。

## 4. 新类目：从识别到首次采集

1. 在VMLogin的Temu页面打开目标类目，确认商品已加载。
2. 手动插件点击“识别当前类目”。这一步只是识别页面，不是保存商品。
3. 回运营台上方“快速使用当前 Temu 类目”，核对类目名称、路径和识别时间。
4. 点击“选择当前类目”。如识别过期或仍是上一个类目，回Temu重新识别，再刷新运营台。
5. 核对上方类目选项。没有正式池的类目通常显示池数量0，按钮为“开始首次采集”；已有未完成首次任务时，按页面提供的继续入口恢复，避免重复创建。
6. 填一个能看懂的任务名，例如“内饰配件－9月10日首采”，点击“开始首次采集”。看到正确的当前任务信息才算创建成功。
7. 回Temu插件，依次点击“检测当前页面”→检查通过后点击“绑定当前页面”→“采集当前页面”。创建任务本身不代表已经采集。
8. 人工滚动或点击Temu的See more，等新商品加载稳定后，再点“采集当前页面”。重复这一过程。

每次点采集，会读取当前页面已加载且符合提交条件的商品，不只读取眼前一行。已经提交过的商品可能再次出现，系统按商品ID去重，所以看到“重复”数量增加通常正常。

识别失败时的备用入口：“高级：手工创建 Category Profile”。填写页面真实名称、英文别名、父类目、面包屑路径和类目URL，先“验证类目配置”，再“保存并创建首次采集任务”。不确定这些内容时，不要猜填，先让维护人员核对。

## 5. 首次采集结束：建立首个正式池

1. 在运营台核对当前任务名称和已采集数量。
2. 点击“检查首批商品质量”。
3. 质量检查通过且按钮可用后，点击“建立首个商品池”。如果检查后又继续采集，数据版本可能变化，需要重新检查。
4. 看到建立成功及正式池数量后，才算获得可以导出、创建跟踪计划的正式池。
5. 如果质量检查失败，按失败项处理，不要把“导出当前采集预览”当成已经建立正式池。

“导出当前采集预览”用于看尚未正式建立的首采数据；“导出正式商品池”读取已建立的正式版本。按钮是否可用取决于当前任务类型及状态。

## 6. 继续旧任务与创建补充任务有什么区别

### 继续旧任务

在下方“已有手动任务”选中正确任务，点击“切换 / 继续所选任务”。原已采数量保留，不用重新建任务。回Temu重新检测、绑定后继续采集。旧任务已经是当前任务、绑定仍有效时，可以直接继续采集。

### 另建补充新品任务

上方的“继续补充商品（创建新任务）”会创建另一轮按目标数量执行的任务，不是恢复旧进度。

例如正式池267件，“本次新增目标数量”填300，则目标总量为567件。原池已有商品不计入这300件新品。创建后仍需在插件人工检测、绑定和采集，正式池不会立即变成567件。

该入口要求正式池及类目关联一致，并且没有其它采集任务占用。它采用独立的扩容流程；页面没有提供后续质量检查/发布入口时，不要以为导出就能完成入池。日常运营优先使用“复采→预览合并→确认合并”的完整流程。复采合并入口只接受复采任务，不接受补充任务。

## 7. 换类目、释放“活跃队列”占用

出现“有活跃队列”时，不用关闭VMLogin，也不用删除数据。

1. 滚到下方“已有商品复采（周期跟踪）”区。
2. 点击“刷新任务”，查看标记为“当前任务”的名称。
3. 点击“暂停当前任务，释放采集占用”。此按钮暂停的是实际当前任务，不是随便选中的旧任务。
4. 等待“占用已释放”的提示，再回上方创建新类目任务。
5. 以后恢复：选择被暂停的旧任务，点击“切换 / 继续所选任务”，重新检测、绑定。

正在保存、检查或导出时，系统会拒绝中途暂停；等该操作结束再点。若提示“当前任务已变化”，先刷新任务列表再操作，不要连续点击。

“暂停计划”暂停的是周期数据归档；“暂停当前任务，释放采集占用”暂停的是采集任务。这两个按钮用途不同。

## 8. 已有商品：周期复采

1. 若还没有跟踪计划，先去“周期跟踪”选择正式池并创建计划，保存当时的商品范围和基线。
2. 点击计划旁的“复采当前计划商品 →”，会返回采集页面并选中对应正式池。这个按钮只帮助定位，不会开始采集。
3. 在下方核对正式池的类目和件数，点击“创建复采任务并切换”；如果已建过同类目复采任务，也可从“已有手动任务”继续它。
4. 打开Temu对应类目，插件重新检测、绑定，再人工采集、滚动和点击See more。
5. 复采任务不要求新增300件。已经在跟踪计划范围内的商品，只要采到就可以更新历史。

没采到某件商品只表示这次没有观察到，不能据此判断下架。复采商品数量也可能多于正式池：页面可能同时出现已有商品和新品。

## 9. 把复采新品合并正式池，并跟踪新范围

1. 下方“已有手动任务”选中需要合并的复采任务，注意不要选错类目。
2. 点击“预览所选复采任务的合并结果”。预览不会改数据库中的正式池版本。
3. 阅读原池数量、本次采集数量、新品数量、已有商品更新数量、排除数量以及合并后总数。
4. 确认是目标任务后，点击“确认合并到正式池”。
5. 合并成功后，点击“为合并后的商品池创建跟踪计划”。若建计划失败但合并已成功，只需重试建计划，也可去周期跟踪手动选择新池，不用重新采集或再次合并。

合并规则：原池商品全部保留；本次合格新品按商品ID去重加入；已有商品优先用更新的采集数据；原池本次没采到的商品仍保留；新池保存独立数据副本。电子/电气筛选未通过的新品不加入，但不会借这次合并批量清理原池历史商品。

例：原池121件，本次采到236件，其中90件原池已有、146件是新品。合并后是121＋146＝267件，而不是236件。旧池中31件本次没采到，也保留。

原池版本和旧跟踪历史保留。原121件的计划不会自动变成267件；需要为新267件池创建新计划。新计划以创建时的最新池数据为基线，旧计划保留原来的起点。是否暂停旧计划，由运营人员根据是否还需要继续跟踪旧范围决定。

预览后如果继续采集，数据改变了，确认合并可能提示“重新预览”。这是为防止按过期数量合并，重新预览即可。

## 10. 看懂周期跟踪、曲线和数字

### 每天怎么查看

1. 选择正确的“当前计划”。
2. 点击“刷新记录”。运营台服务运行时后台也会自动归档。
3. 看“累计复采记录（不限日期）”，这里显示实际更新过的商品数量和后续观测条数。
4. 点击“查看已更新商品”，或将对比周期选为“最新数据 vs 基线”。
5. 在商品行点击“查看”，选择价格、展示销量、评论数或评分曲线。
6. 需要分析或交接时，点击“导出周期 Excel”。

### 哪些重复会合并

同一天同一商品的价格、币种、展示销量、评论数和评分都相同，不因反复点击采集增加趋势点。同日指标真的变化时保留；隔天即使指标没变，也保留复采记录。日期按北京时间划分。原始采集证据仍保留，趋势和Excel采用合并后的历史。

### 常见数字区别

| 显示 | 含义 |
| --- | --- |
| 插件“收到” | 本次提交的商品记录数，可能包含之前已提交的商品 |
| 插件“新增” | 本任务此次新增的有效去重商品，不等于新正式池增加数 |
| 插件“重复” | 本任务已有商品再次出现，不等于采集失败 |
| “业务排除” | 被筛选规则排除的商品，例如电子设备和电气配件 |
| 当前已采集 | 当前任务保存的有效去重商品数；复采和补充任务的计数口径不同 |
| 正式池数量 | 已建立的正式版本商品数，不会因为点击采集自动改变 |
| 跟踪“已更新商品” | 固定计划范围内获得后续观测的商品数 |
| 后续观测条数 | 去除同日相同指标重复后的历史条数，一件商品可有多条 |
| 本次同步新增0条 | 当前没有尚未归档的新记录，可能已被后台归档，并不代表没采到 |

第7、14、21天卡片只用于阶段对比；未到期显示0不影响日常历史。每阶段取对应时间窗口内首次有效观测，完整过程请看曲线明细。

只有基线一个点，说明该商品还没有后续观测。基线时间可能早于创建计划时间，因为来自原商品采集日期。字段“—”表示缺失，不能当作0。展示销量可能是取整值，差额不能当成精确成交量；价格只在币种一致时计算变化。

跟踪保留原池商品的原始观测，包括业务排除项，因此跟踪更新数可能与插件筛选后的数量不同。新品尚未加入计划前，不会自动扩大旧计划的范围。

## 11. 导出Excel和下载主图

“导出正式商品池”导出当前选定类目已经建立的正式池；导出不会建立池、不会合并新品、不会创建跟踪计划。合并后请刷新页面，核对正式池数量再导出。

“已有导出”中保留旧文件记录，日期和件数不同是不同批次。不要把旧121件文件当作新267件文件。

主图下载：选择已有导出→按需“选择图片下载目录”→“下载 JPG 图片（本机下载）”→完成后“打开图片目录”。这是本机下载，不是让VMLogin浏览器保存图片。下载仍需要网络；失败时按页面显示的结果处理。

## 12. 常见问题与处理

| 现象 | 先怎么做 |
| --- | --- |
| 开始首次采集提示活跃队列 | 按第7节暂停当前任务并释放占用，再创建 |
| “当前类目不可采集”或配置显示不可用 | 看错误原因；可能是类目关联与正式池不一致，不是Temu禁止该类目。不要乱建同名配置绕过检查 |
| 旧摩托车配件池不能新建补充任务 | 当前存在历史关联问题。可以继续已有复采任务，后续用复采合并流程；关联修复交维护人员处理 |
| 插件绑定/采集按钮灰色 | 先确认有正确运行任务，再检测页面；检测通过才能绑定，绑定后才能采集 |
| 页面有商品但检测未通过 | 看失败项：站点、语言、币种、排序、类目、网络证据。按提示处理后重检，不要只反复点采集 |
| Extension context invalidated | 插件更新后旧页面脚本失效，刷新Temu页面后重新检测和绑定 |
| Try again、验证码、空列表 | 人工处理页面异常，恢复正常商品列表后再检测；不要提交空页面 |
| 新增0件、重复很多 | 可能当前已加载商品都提交过了。人工See more加载新商品，稳定后再采 |
| 业务排除很多 | 当前按要求排除所有带电产品及电气配件；车灯、开关、保险丝、耳机等都会命中。需要改经营范围时先调整筛选规则 |
| 跟踪刷新显示0条 | 看累计记录及“最新数据 vs 基线”，不要只看7/14/21卡片 |
| 合并后旧跟踪计划还是原件数 | 正常；旧计划范围固定，为新池另建计划 |
| 暂停后下面还看到旧任务信息 | 核对任务列表的“已暂停”和占用释放提示；任务保留是正常的，等页面刷新，不要删除 |
| 新类目识别成上一个类目 | 在新Temu页面重新点“识别当前类目”，核对识别时间后再选择 |

无法处理时，把“任务名称、类目、操作步骤、完整错误提示、发生时间”一起发给维护人员；不要只发“不能采集”。

## 13. 每天下班与换电脑

下班：等当前保存/导出完成→在运营台暂停当前任务释放占用→确认数据已保存→需要时导出报表。关闭网页不等于暂停后台任务；暂停采集任务不等于停止整个运营台服务。

数据保存在本机数据库，Excel只是报表。主数据库：`state/data/temu_research_v2.db`；跟踪数据库：`state/data/period-tracking.db`。两个数据库、程序、配置及本地图片文件都属于交接范围。

换电脑不会自动同步。交给维护人员先停止服务，再备份整个工作目录及两个数据库；若服务仍在运行，不能只复制.db而忽略SQLite写入状态，应使用一致性备份。新电脑需要调整本机路径和浏览器/插件配置。仅有Excel不能恢复完整任务、跟踪计划和历史。不要将包含账号配置的整个目录随意发到公开位置。

## 14. 运营每日检查清单

1. 选对类目、选对任务；新任务与继续旧任务不要混用。
2. Temu页面正常，德国/English/EUR/Top Sales正确。
3. 先检测、再绑定、再采集；人工See more之后等加载稳定。
4. 关注新增、重复和排除，发现异常先查原因。
5. 新品需要入池时先预览合并，核对任务名和总数后确认。
6. 新正式池需要跟踪时，创建对应新计划；查看累计观测确认数据。
7. 导出时核对文件日期、类目和件数。
8. 换任务或结束工作时暂停释放占用，保留数据和旧任务。


## 15. 根据销量增长查找机会商品并进入 1688 复核

1. 打开“周期跟踪”，选择需要分析的跟踪计划。
2. 在“按销量增长发现机会商品”选择近 7 天、近 30 天（一个月），或填写自定义起止日期。日期按北京时间计算，近 7 天包含今天和前 6 天，近 30 天包含今天和前 29 天。
3. 将“展示销量至少增加”设为 1000，点击“筛选机会商品”。达到或超过阈值的商品按增量从高到低排列。
4. 查看每行的实际观测起止时间与跨度。系统比较选定窗口内最早和最新的有效销量记录，不会把窗口外的旧基线混进来，也不会按天数推算。窗口内只有一次有效观测会归为数据不足；销量发生回退的商品列入需复核数量。
5. 点击“查看趋势”检查历史曲线；点击“去 1688 人工复核”按 Temu 商品 ID 查找已有候选批次，跳转并选中对应商品，左侧黄色边框显示定位结果。存在多个批次时优先使用接口返回的最新批次。
6. 如果提示尚无候选，先为该商品导入 1688 候选再复核；不会跳转到其他商品代替。普通周期对比列表也提供“1688 复核”入口。

展示销量可能取整，窗口内增量不是精确成交量。实际观测间隔短于所选日期范围时，不代表已覆盖完整周期。此筛选结果用于发现线索，不会自动更改商品池或人工复核结论。


## 日志系统与报错处理（2026-09-10 更新）

左侧“日志系统”用于查看运营台、自动截图队列和差评采集的状态。打开页面后每 15 秒查询一次；页面关闭后不持续轮询。无法连接表示暂时查询不到，不表示任务已经停止。

遇到报错时：
1. 记下报错时间和当时操作的商品或任务，并截图。
2. 打开“日志系统”，点击“刷新日志”。按级别或关键词查找相关记录。
3. 点击“导出排查日志”，把 JSON 文件和报错截图一起交给维护人员。

持久日志覆盖运营台 API 的修改操作和失败请求，记录时间、模块、接口路径、HTTP 状态、错误代码、耗时及排查编号。正常的查询请求不逐条记录，避免状态刷新淹没日志。截图及差评采集的完整内部历史仍在各自任务记录中；导出会附带当前任务状态。

本机日志目录：F:\TemuWindows\handoff-20260907\state\logs。operator-system.jsonl 保存结构化日志，最多保留当前及上一份各约 5 MB；页面返回最近 2000 条。operator-stdout.log 和 operator-stderr.log 是本次启动的进程输出，供维护人员进一步排查。日志不记录请求正文和 URL 查询参数。数据不会自动同步到其他电脑。

手工新建类目仅在自动识别不可用时使用。填写运营显示名称、Temu 页面上的类目名称、页面顶部类目路径和类目页面链接。类目路径例：Home > Automotive > Replacement Parts。父类目自动取路径中的上一级，不必再填；Temu 类目名称请照原文填写。


## 按商品池建立 1688 复核批次

1. 在“1688 候选导入”选择本批对应的正式商品池，核对类目、件数、建池日期及当前/历史版本。
2. 批次名称可填写“替换零件 9月第一批”，留空则自动命名。
3. 每个类目的 1688 Excel 分文件夹存放，文件名仍为 Temu 商品 ID.xlsx。
4. 扫描检查，再导入。文件里的商品 ID 必须属于所选商品池；更换池后必须重新扫描。
5. 每次成功导入形成独立复核批次，在人工复核顶部选择批次。此前的确认结果仍保留。

旧批次没有可靠的商品池关联时，显示“历史批次（未关联商品池）”，不自动推断归属。
