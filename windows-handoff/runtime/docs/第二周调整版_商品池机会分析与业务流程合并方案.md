# 第二周调整版执行方案：商品池机会分析 → 机会产品确认 → 差评与1688并行

版本：V1.0
日期：2026-08-27
适用项目：Temu 自动化选品系统
依据：
- 《商品池机会分析方法手册》
- 《第二周调整方向》

---

# 0. 文档定位

本文件用于把《商品池机会分析方法手册》的选品方法，与《第二周调整方向》会议中确认的业务流程合并成一套可直接执行的第二周方案。

本次调整的核心不是推翻现有技术成果，而是修正业务节奏：

```text
原先偏早：
商品池
→ 评论采集
→ 再判断机会

调整后：
商品池
→ 清洗/去重/重分类
→ 场景与细分机会分析
→ 找到具体机会产品
→ 内部人工确认
→ 差评抓取 + 1688寻源并行
```

本版本的核心原则：

> 评论不是第一轮筛选工具，而是“机会产品已经确认之后”的验证工具。

---

# 1. 第二周目标重新定义

第二周的核心目标不再是“抓更多评论”，而是：

1. 把当前商品池清洗成可信的数据底座。
2. 按真实消费场景重新分类。
3. 再拆到真实细分产品类型 / 物理形态。
4. 在细分层计算市场容量、商业效率、竞争强度和评论壁垒。
5. 筛出 3—5 个值得继续验证的机会产品方向。
6. 再从每个方向落到具体商品。
7. 由内部需求方确认“这个产品值得做”。
8. 确认后，差评抓取与 1688 寻源同时启动。
9. 最后把“用户痛点”和“供应商可解决能力”合并，形成最终选品判断。

# 3. 第一层：先把数据变得可信

## 3.1 必须保留的原始字段

至少保留：

- 商品名
- 商品链接
- 图片
- 价格
- 累计销量
- 评分
- 评价数

可获得时保留：

- 重量
- 包装尺寸
- 车型
- 品牌
- 上架时间

没有的数据必须标记：

```text
未知
```

不得推测成事实。

## 3.2 数据清洗

必须完成：

### 价格

- 统一币种
- 排除空值
- 排除0元
- 排除明显异常值
- 明确促销价口径

### 销量

- 明确累计销量还是周期销量
- 文本销量转成数值

### 评分与评价

- 空值不当成0
- 评价数不能代替销量

### 重复商品

当前系统仍以：

```text
platform + goods_id
```

作为稳定商品身份。

不得以 URL 作为商品唯一身份。

### 图片与链接

必须保留作为证据。

最终任何推荐都应能够回到：

- 原商品
- 图片
- 链接
- 原始数据

# 4. 第二层：按真实消费场景重新分类

平台类目只能作为参考。

真正分析时应优先问：

```text
用户为什么买？
```

而不是只问：

```text
平台把它归在哪个类目？
```

## 4.1 一级消费场景示例

### 骑行电子

例如：

- 蓝牙耳机
- 手机支架
- 导航/仪表
- 行车记录
- 电子防盗

当前业务规则下，这类多数属于排除范围，不进入后续推荐。

### 骑行收纳

例如：

- 尾包
- 油箱包
- 边包
- 工具收纳包
- 硬箱与安装架

### 维修保养

例如：

- 补胎套装
- 链条工具
- 火花塞工具
- 清洁养护
- 维修组合工具

### 安全防护

例如：

- 轻小防摔件
- 车身保护件
- 重型护杠
- 车罩
- 防盗锁

### 照明

例如：

- 前照灯
- 辅助灯
- 转向灯
- 尾灯
- 灯罩/支架

当前阶段电子照明默认不做。

### 电气供电

例如：

- USB充电器
- 点烟器
- 电压表
- 线束
- 开关
- 继电器

当前阶段默认排除。

### 控制操纵

例如：

- 手把
- 拉杆
- 脚踏
- 换挡/刹车控制件

### 外观改装

例如：

- 贴花
- 装饰盖
- 风挡
- 后视镜
- 车身造型件

# 5. 分类方法：规则初分 + 高价值复核

采用两段式分类：

## 第一步

使用规则和关键词快速覆盖大部分商品。

## 第二步

重点复核：

- 高GMV商品
- 高销量商品
- 模糊命名商品
- 边界商品

复核信息来源：

- 标题
- 图片
- 商品物理形态
- 使用场景

## 5.1 典型误判

需要特别防止：

```text
reflective
```

不一定是照明，可能只是车罩反光条。

```text
polished
```

不等于清洁产品，可能只是“抛光表面”。

```text
air cleaner
```

通常是空气滤清器，不是清洁剂。

```text
tool bag
```

是工具收纳，不等于维修工具。

```text
crash bar bag
```

是装在护杠上的包，不是护杠本身。

```text
ignition alignment tool
```

应按维修工具判断，不应归入电气供电。

# 6. 第三层：真正的机会判断必须发生在细分产品类型

这是本版本最重要的分析原则之一。

不能：

```text
骑行收纳很好
→ 所有收纳产品都值得做
```

也不能：

```text
安全防护GMV高
→ 所有安全防护都值得做
```

必须继续拆：

```text
一级场景
↓
真实产品类型
↓
物理形态
↓
车型 / 通用属性
```

例如：

```text
安全防护
↓
轻小防摔件
↓
防摔球 / 轴保护块 / 前叉滑块
```

或者：

```text
骑行收纳
↓
尾包 / 后座包 / 油箱包 / 边包 / 工具包
```

机会判断必须在这个层级重算指标。

# 7. 细分机会指标体系

## 7.1 商品数

```text
细分类型内有效SKU数
```

回答：

> 同质竞争密度有多高？

注意：

```text
SKU数 != 卖家数
```

## 7.2 总销量

```text
Σ销量
```

回答：

> 这个细分需求规模大不大？

## 7.3 平均销量

```text
总销量 ÷ 商品数
```

只能看总体产出。

容易被爆款拉高。

## 7.4 中位销量

销量排序后的中间值。

这是非常重要的指标。

如果：

```text
平均销量很高
但
中位销量很低
```

说明市场可能主要靠少数爆款支撑。

因此：

> 对新进入者，中位销量通常比平均销量更有参考价值。

## 7.5 平均售价

```text
Σ价格 ÷ 商品数
```

回答：

> 价格带是否有商业空间？

## 7.6 估算 GMV

商品级：

```text
当前价格 × 累计销量
```

细分级：

```text
Σ(价格 × 销量)
```

注意：

估算GMV用于商品池内部横向比较。

不等于：

- 真实周期销售额
- 实际到账收入
- 扣除退款后的销售额

## 7.7 GMV / SKU

```text
估算GMV ÷ 商品数
```

回答：

> 每一个在售商品平均能分到多少价值？

这个指标非常适合判断：

```text
款式少
但
市场价值不低
```

的机会。

## 7.8 平均评分

用于判断：

- 市场成熟度
- 用户满意门槛

高评分不一定等于机会大。

高评分也可能意味着：

```text
用户要求高
市场已经成熟
```

## 7.9 平均评价数

回答：

> 市场的社会证明壁垒有多高？

## 7.10 评论密度

```text
评论密度 = Σ评价数 ÷ Σ销量
```

老板会议中特别强调了类似：

```text
评价数 ÷ 销量
```

这个方向。

当：

```text
销量很高
但评价相对少
```

可以作为：

```text
近期动销较快 / 评论积累壁垒较低
```

的参考信号。

但不得直接描述为真实近期销量。

## 7.11 Top3销量占比

```text
Top3销量 ÷ 细分总销量
```

回答：

> 头部是否控制了大部分需求？

这是老板当前特别重视的指标。

---

# 8. 大类低集中，不等于细分好进入

这是老板会议和方法手册共同强调的原则。

例如：

```text
安全防护
```

整体 Top3 可能较低。

但里面混合：

- 车罩
- 防摔件
- 护杠
- 防盗
- 保护盖

不同产品的真实竞争完全不同。

因此必须：

1. 先看一级场景容量。
2. 再拆真实产品类型。
3. 在细分里重新计算：
   - 商品数
   - GMV
   - GMV/SKU
   - 中位销量
   - Top3
4. 再打开头部商品确认：
   - 是单链接强？
   - 品牌强？
   - 车型系统壁垒？
   - 知识产权？
   - 还是产品本身确实跑得快？

---

# 9. Top3高到底意味着什么

Top3高不能简单理解为：

```text
一定不能做
```

必须继续判断头部优势来源。

## 9.1 单链接运营优势

信号：

- 单条链接占比高
- 品牌没有连续占据多个头部
- 产品造型常规

含义：

可能可复制。

重点学习：

- 价格
- 图片
- 评价积累
- 上架时间

## 9.2 品牌 / 渠道垄断

信号：

- 同品牌多条链接长期占据头部
- 价格体系稳定

含义：

需要品牌或渠道资源。

不建议简单做同款。

## 9.3 车型 / 安装系统壁垒

信号：

- 专用支架
- 专用接口
- 生态配件
- 车型依赖

含义：

需要车型适配表和配套系统。

## 9.4 知识产权壁垒

信号：

- 独特结构
- 独特外观
- 商标
- 图案
- 专有安装结构

含义：

未经专业检索不能直接当成低风险机会。

---

# 10. 物流必须单独拆

不能把所有同场景商品放进同一个机会分。

至少分：

## 10.1 轻小件

例如：

- 轴滑块
- 防摔球
- 护罩
- 小型保护片

重点：

- 车型
- 材质
- 安装位置
- 包装重量

## 10.2 软包 / 可压缩

例如：

- 工具包
- 尾包
- 油箱包
- 边包

重点：

- 面料
- 防水
- 绑带强度
- 容量
- 压缩体积

## 10.3 重型 / 大体积

例如：

- 整车护杠
- 硬箱
- 安装架
- 大型护网

重点：

- 实重
- 体积重
- 国际运费
- 破损
- 海外仓 / 平台仓

当前业务应优先考虑：

```text
轻小件
+
软包
```

重型商品需要额外人工核验。

# 11. 知识产权与车型适配必须作为独立风险

系统只负责：

```text
提示需要核查
```

不能证明：

```text
无侵权
```

至少关注：

- 商标
- 车型兼容表述
- 版权
- 外观设计
- 实用/发明专利
- 车型年份
- 孔距
- 接口
- 左右侧

最终开发前必须单独做专业检索或人工审核。

# 12. 机会指数：用于排序，不代替业务判断

建议保留一个细分级机会指数。

分项在同层级内做0—100标准化。

对：

- 销量
- GMV
- 评价数

建议先做对数处理，再排名。

初始权重：

| 维度 | 权重 | 组成 |
|---|---:|---|
| 需求强度 | 25% | 总销量60% + 中位销量40% |
| 商业价值 | 20% | 平均售价55% + GMV/SKU45% |
| 进入友好度 | 25% | 商品数反向55% + Top3反向45% |
| 评论空白 | 15% | 平均评价数反向60% + 评论密度反向40% |
| 质量基础 | 15% | 平均评分 |

规则：

- 样本数 < 3 的细分，不进入正式排名。
- 高分不等于立刻开发。
- 高分表示：
  - 值得继续做供应链
  - 值得继续做物流
  - 值得继续做IP
  - 值得继续做适配验证

# 13. 从细分类型落到具体商品

产品类型确认后，再选具体代表商品。

不是：

```text
直接选销量前三
```

而是先过滤：

```text
销量低于该细分中位数
```

再做商品级机会分。

初始参考：

| 维度 | 权重 |
|---|---:|
| 需求验证 | 35% |
| 商业价值 | 30% |
| 质量基础 | 15% |
| 评论空白 | 20% |

其中：

### 需求验证

销量对数分位。

### 商业价值

```text
估算GMV 60%
+
售价 40%
```

### 质量基础

评分。

### 评论空白

```text
评价数反向60%
+
评论密度反向40%
```

# 14. 候选商品必须带完整证据

每个具体候选商品必须呈现：

- 原始商品名
- 可点击链接
- 图片
- 单价
- 销量
- 评价数
- 评分
- 估算GMV
- 车型/年份/通用性
- 物流形态
- 主要机会理由
- 主要风险

无法识别的内容：

```text
需核实
```

不得猜测。

# 15. 最终推荐不能只给一个排行榜

最终应分层：

## 核心规模机会

条件：

- 容量大
- 中位销量高
- 价格带成立
- 竞争不过度集中

动作：

立即做：

- 供应链
- 成本
- 样品验证

## 差异化机会

条件：

- 市场成熟
- 但用户痛点 / 同质化明显

动作：

先定义差异化方向，再找供应链。

## 验证机会

条件：

- SKU少
- GMV/SKU高
- 但样本少或车型覆盖有限

动作：

小批量测试 + 外部验证。

## 谨慎 / 观察

条件：

- 头部品牌/IP强
- 物流不经济
- 车型适配复杂
- 评分门槛高

动作：

暂缓。

# 17. 评论采集的新定位

以后不是：

```text
对大量商品抓全部评论
```

而是：

```text
只针对已确认机会产品
抓差评
```

会议当前要求：

```text
好评可以不抓
重点只抓差评
```

差评分析必须输出：

- 痛点主题
- 痛点次数
- 痛点比例
- 原始评论证据
- 是否可通过产品改进解决

例如：

```text
“太薄”
占负面评论50%
```

则后续供应商沟通可以直接问：

```text
“买家经常反馈这个产品太薄，
你们有没有加厚版本？
是否支持改材质/改厚度？”
```

---

# 18. 1688寻源与差评同步开始

内部确认产品后：

```text
差评
```

和：

```text
1688
```

应该同时进行。

因为二者要互相验证。

## 差评回答

```text
用户哪里不满意？
```

## 1688回答

```text
供应商能否解决？
解决成本是多少？
有没有现货？
MOQ是多少？
交期多久？
```

# 19. 1688供应商固定问题模板

会议已经提出固定问题标准化的方向。

至少包括：

1. 你们是工厂还是贸易商？
2. MOQ是多少？
3. 是否有现货？
4. 交期多久？
5. 售后如何处理？
6. 是否支持定制？
7. 当前核心痛点能否解决？
8. 如果需要改材质/规格，成本增加多少？

后续可将：

```text
固定问题
+
当前产品痛点
```

自动生成供应商询盘内容。

# 23. AI的正确位置

AI分两次使用。

## 第一次：机会分析阶段

AI主要用于：

- 模糊商品分类
- 真实消费场景判断
- 物理形态判断
- 物流形态提示
- 风险解释
- 机会结论解释

AI不负责计算：

- 销量
- GMV
- 中位数
- Top3
- GMV/SKU
- 评论密度

这些由程序确定性计算。

## 第二次：机会产品确认后

AI用于：

- 差评主题
- 痛点聚类
- 痛点归因
- 可改进性
- 供应商问题生成
- 产品卖点建议

# 27. 最终判断原则

好的选品结论不是：

```text
“这个市场销量很高”
```

而是：

> 在足够细的真实竞争单元里，需求、客单价和商业效率成立；头部优势可解释且可复制；物流、车型适配和知识产权风险在能力范围内。

只有满足这个条件，产品才值得进入：

```text
差评
+
1688
+
采购
```

阶段。
