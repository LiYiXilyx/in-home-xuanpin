# Temu 独立 Chrome 搜索或类目无商品：原因总结与排查手册

## 1. 现象

从选品运营台启动独立 Chrome 后，Temu 首页和页面框架能够打开，但搜索或进入类目时经常出现以下情况：

- `Please check your network connection and try again.`
- `No results for "..."`
- `Oops! The items are gone.`
- 登录页或 `Security Verification` 人工验证码页
- 日常 Chrome 可以显示商品，而运营台独立 Chrome 在相同网络下不显示商品

这里的“独立 Chrome”使用单独的 `user-data-dir` 和调试端口。它与日常 Chrome 是两个不同的浏览器环境，不共享 Cookie、登录状态、本地存储、站点偏好和大部分扩展配置。

## 2. 结论

这类问题通常不是“整个网络断开”，也不能仅凭页面现象断定是 CDP 或运营台代码导致。更常见的是以下因素叠加：

1. 独立 profile 的 Temu 会话、地区和风控状态与日常 Chrome 不同；
2. 类目 URL 携带了只对原会话有效或很快过期的参数；
3. 页面框架加载成功，但商品搜索、库存或推荐接口请求失败或被限制；
4. 独立 Chrome 没有继承日常 Chrome 的代理、VPN、扩展或 DNS 行为；
5. Temu 的地区库存、类目路由或服务本身短时不稳定。

本次实际现象中，旧独立 profile 能登录并识别为 `READY`，但类目页显示商品已消失，搜索页又显示网络错误和无结果；换用新的独立 profile、重新人工设置站点并从页面内正常进入类目后，商品列表能够显示并完成采集。因此最可能是“独立 profile 会话状态 + 会话型 URL + Temu 对该环境的网络或风险判断”共同造成，而不是已证实的单一故障。

## 3. 原因分析

### 3.1 独立 profile 与日常 Chrome 不共享站点状态

独立 profile 是为了避免复制日常浏览器中的敏感 Cookie 和个人数据。代价是首次启动时它相当于一台新浏览器：

- 需要重新人工登录；
- 需要重新选择国家、语言和币种；
- 可能重新触发验证码；
- Temu 会重新建立设备、会话和实验分组状态；
- 日常 Chrome 中生效的代理或扩展不一定在独立 profile 中生效。

所以“日常 Chrome 正常”不能直接证明“独立 Chrome 的会话也正常”。

### 3.2 复制的类目 URL 可能绑定原会话

Temu URL 中经常包含 `_x_sessn_id`、`refer_page_id`、`refer_page_sn`、`refer_page_name` 等跳转和会话参数。这些参数可能过期、绑定来源页面，或只在生成它们的 profile 中有效。

把日常 Chrome 的完整 URL 原样粘贴到独立 Chrome，路径看似相同，但后端可能无法复用原上下文，从而返回空类目或“items are gone”。因此应优先从独立 Chrome 的首页和站内菜单重新进入目标类目，而不是长期复用带会话参数的完整链接。

### 3.3 页面框架正常不代表商品接口正常

截图中导航栏、搜索框和账户区域已经显示，说明 HTML 和部分静态资源加载成功。但商品列表往往来自后续的搜索、库存、推荐或地区接口。只要这些接口超时、返回限制状态或被风控拒绝，就可能同时出现：

- 页面上方提示检查网络；
- 页面主体显示无搜索结果；
- 类目页显示商品已消失。

这时不应把“无结果”当作真实的零库存，也不应持久化为空采集结果。

### 3.4 地区、语言、币种和登录上下文不一致

德国站、英语和欧元不仅是界面显示，它们还会影响可售库存、配送区域和搜索结果。界面右上角看起来正确，也不保证独立 profile 中的所有后端上下文已经同步。刚登录、刚切站点或验证码完成后，旧页面仍可能保留过期状态，需要在同一独立 profile 中重新从首页进入。

### 3.5 代理、VPN、扩展或网络路径不一致

日常 Chrome 可能使用系统代理、VPN 扩展、广告过滤规则或特定 DNS，而独立 Chrome 未必具备完全相同的路径。典型表现是：

- 两个 Chrome 同时打开，但只有一个能获得搜索结果；
- 首页正常，商品接口失败；
- 换网络或稍后重试后恢复。

排查时可以比较配置，但不要复制日常 Chrome profile，也不要导出或打印 Cookie、Token。

### 3.6 Temu 风控或人工关卡

新 profile、短时间多次搜索、频繁刷新或异常导航都可能触发登录或 Security Verification。系统必须暂停并等待人工处理，不能绕过验证码。验证码完成并不保证旧请求会自动恢复，通常需要人工刷新或从首页重新导航。

### 3.7 临时服务、地区库存或类目路由变化

Temu 的搜索结果和类目库存与地区、时间和商品上下架有关，类目地址也可能调整。若日常 Chrome 和独立 Chrome 同时失败，优先考虑 Temu 临时故障、网络出口或地区可售性，而不是 profile 本身。

## 4. 快速判断矩阵

| 现象 | 优先怀疑 | 建议动作 |
| --- | --- | --- |
| 日常 Chrome 正常，独立 Chrome 失败 | profile 会话、地区、代理或风控差异 | 在独立 Chrome 中重新登录、设置站点并从首页导航 |
| 两个 Chrome 都失败 | 网络出口、Temu 服务或地区库存 | 停止采集，稍后重试并检查网络 |
| 首页正常，搜索和类目都失败 | 商品接口、会话或风险限制 | 不把空结果入库，保存非敏感诊断信息 |
| 出现登录页或验证码页 | 人工关卡 | 暂停任务，由人工完成后再继续 |
| 复制完整类目 URL 后失败 | URL 含过期或会话型参数 | 删除来源参数或从站内菜单重新进入 |
| 新独立 profile 正常、旧 profile 失败 | 旧 profile 缓存或站点状态损坏 | 保留旧 profile，改用新的独立 profile |

## 5. 推荐恢复步骤

1. 确认当前操作的是运营台启动的独立 Chrome，不要同时让两个自动化实例使用同一个 profile 或调试端口。
2. 在独立 Chrome 中人工打开 Temu 首页。
3. 人工登录，并确认目标国家、语言和币种。
4. 如出现验证码，由人工完成；程序不得点击、识别或绕过验证码。
5. 不粘贴带 `_x_sessn_id` 等参数的旧完整 URL，优先从独立 Chrome 的 Categories 或站内搜索重新进入。
6. 等商品卡片真实显示后，再选择 Top Sales，并再次人工确认页面、类目和排序。
7. 先运行只读 smoke/page validation；只有状态为 `READY` 且列表验证通过，才开始采集。
8. 如果仍失败，关闭占用该 profile 的 Chrome，换一个新的独立 profile 目录和未占用的调试端口重试。不要删除旧 profile。
9. 如果两个浏览器都失败，停止反复刷新，稍后重试或检查允许使用的网络环境。

## 6. 系统应如何处理

运营台和采集程序应把这些页面当作失败或人工关卡，而不是有效的空列表：

- `CAPTCHA_OR_LOGIN`：需要人工登录或验证码；
- `NETWORK_ERROR`：商品接口或页面提示网络错误；
- `ACCESS_RESTRICTED`：访问受限或风险页；
- `LISTING_NOT_FOUND`：没有识别到有效商品列表；
- `WRONG_PAGE`：不是目标 Temu 类目页；
- `SORT_NOT_CONFIRMED`：不能确认 Top Sales。

遇到上述状态时应：

- 停止持久化商品；
- 保持人工在环，不自动猜测类目或切换页面；
- 在 Git 忽略的 `outputs/debug/<job_id>/` 保存失败截图和必要 HTML；
- 日志只记录脱敏 URL、错误码和时间，不记录 Cookie、Token 或账户敏感信息；
- 允许人工修复页面后恢复任务。

## 7. 不建议的做法

- 不复制日常 Chrome 的整个用户 profile；
- 不导入、输出或提交 Cookie、Token；
- 不尝试自动破解或绕过验证码；
- 不把“无商品”页面当作真实采集结果写入数据库；
- 不高频刷新、搜索或滚动；
- 不长期保存并复用带会话参数的 Temu 完整 URL；
- 不因为一次成功就假定以后不会再次触发人工关卡。

## 8. 人工验收清单

- [ ] 独立 Chrome 使用专用 profile 和唯一调试端口
- [ ] 已人工登录，未复制日常 profile
- [ ] 国家、语言、币种符合目标市场
- [ ] 当前 URL 属于 `temu.com`
- [ ] 当前页面确实是目标摩托配件类目
- [ ] Top Sales 已由人工确认
- [ ] 页面中真实显示商品卡片，而不是空结果或错误占位页
- [ ] smoke/page validation 返回 `READY`
- [ ] 出现验证码时任务能够暂停等待人工
- [ ] 日志和调试文件不包含 Cookie、Token

## 9. 后续工程建议

为了降低复发成本，可在不改变人工在环原则的前提下补充：

- 对搜索/类目接口失败、空结果占位和验证码页建立明确检测规则；
- 对 URL 中的会话型参数进行日志脱敏和持久化前清理；
- 在运营台展示当前 profile 路径、调试端口、站点、语言、币种和页面状态；
- 记录连续失败次数，并在阈值后提示更换独立 profile 或人工检查网络；
- 增加“只验证当前页面、不采集”的按钮，避免排障时误启动真实任务。

这些改进应作为独立任务评审，不应为了排查临时故障而绕过既有页面验证和人工关卡。
